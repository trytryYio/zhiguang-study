## 概念理解

### 什么是前后端拦截？

#### 后端拦截（Spring Security）

**作用：** 保护 API 数据访问

**原理：**
```java
// 后端代码示例
@GetMapping("/api/v1/knowposts/mine")
public ResponseEntity<?> getMyPosts() {
    // Spring Security 自动检查请求头
    // Authorization: Bearer <token>
    // 如果没有 token 或 token 无效，返回 401
    return ResponseEntity.ok(data);
}
```

**保护内容：**
- ✅ API 端点
- ✅ 数据访问
- ✅ 业务逻辑

#### 前端拦截（ProtectedRoute）

**作用：** 优化用户体验

**原理：**
```typescript
// 前端代码示例
const ProtectedRoute = ({ children }) => {
  const { tokens } = useAuth();

  if (!tokens?.accessToken) {
    return <Navigate to="/login" replace />;
  }

  return <>{children}</>;
};
```

**保护内容：**
- ✅ 页面访问
- ✅ 路由导航
- ✅ 用户体验

## 为什么需要双重保护

### 单一后端保护的问题

#### 场景：只有后端保护

```
用户访问 /profile
  ↓
页面加载（显示"请登录后查看你的知文"）
  ↓
调用 API /api/v1/knowposts/mine
  ↓
后端返回 401 Unauthorized
  ↓
前端显示错误或空白
  ↓
❌ 用户体验差
```

**问题：**
1. 用户看到错误信息
2. 页面闪烁（先显示内容再跳转）
3. 不必要的 API 调用
4. 服务器负载增加

### 双重保护的优势

#### 场景：前后端都有保护

```
用户访问 /profile
  ↓
前端检测到未登录
  ↓
立即跳转到 /login
  ↓
✅ 用户体验好
```

**优势：**
1. ✅ 立即跳转，无错误信息
2. ✅ 避免不必要的 API 调用
3. ✅ 减少服务器负载
4. ✅ 更好的用户体验

### 类比说明

| 层面 | 作用 | 类比 | 必要性 |
|------|------|------|--------|
| **后端 Spring Security** | 保护 API 数据 | 家里的防盗门 | ✅ **必须** |
| **前端拦截** | 优化用户体验 | 门铃和欢迎垫 | ✅ **推荐** |

**结论：** 两者都有 = 完整的安全和体验

## 实现方案详解

### 项目现有机制

#### 1. AuthContext（认证上下文）

**位置：** `src/context/AuthContext.tsx`

**功能：**
- 管理用户认证状态
- 提供 `user`, `tokens`, `isLoading`
- 提供 `login`, `logout`, `refresh` 方法

**关键代码：**
```typescript
type AuthContextValue = {
  user: API.AuthUserResponse | null;
  isLoading: boolean;
  tokens: AuthTokens | null;
  login: (payload: API.LoginRequest) => Promise<void>;
  logout: () => Promise<void>;
  refresh: () => Promise<void>;
  reloadUser: () => Promise<void>;
};
```

#### 2. request.ts（请求拦截器）

**位置：** `src/request.ts`

**功能：**
- 自动添加 JWT token 到请求头
- 处理 401 响应
- 统一处理响应结构

**关键代码：**
```typescript
// 请求拦截器
myAxios.interceptors.request.use(
  function (config) {
    const token = getStoredToken();
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  }
);

// 响应拦截器
myAxios.interceptors.response.use(
  function (response) {
    return response.data.data;
  },
  function (error) {
    // 处理 401 错误
    if (error.response?.data?.code === 40100) {
      if (!window.location.pathname.includes('/login')) {
        alert('请先登录');
        window.location.href = `/login?redirect=${window.location.href}`;
      }
    }
    return Promise.reject(error);
  }
);
```

### 需要添加的组件

#### ProtectedRoute 组件

**位置：** `src/components/common/ProtectedRoute.tsx`

**功能：**
- 检查用户认证状态
- 未登录时重定向到登录页

**实现步骤：**

1. **创建组件文件**

3. **检查 tokens.accessToken 是否存在**
4. **处理加载状态**
5. **重定向逻辑**

## 代码示例

### 1. ProtectedRoute 组件

```typescript
// src/components/common/ProtectedRoute.tsx
import { Navigate } from "react-router-dom";
import { useAuth } from "../../context/AuthContext";

interface ProtectedRouteProps {
  children: React.ReactNode;
}

const ProtectedRoute = ({ children }: ProtectedRouteProps) => {
  const { tokens, isLoading } = useAuth();

  // 显示加载状态
  if (isLoading) {
    return <div>加载中...</div>;
  }

  // 未登录，重定向到登录页
  if (!tokens?.accessToken) {
    const redirectUrl = encodeURIComponent(
      window.location.pathname + window.location.search
    );
    return <Navigate to={`/login?redirect=${redirectUrl}`} replace />;
  }

  // 已登录，渲染子组件
  return <>{children}</>;
};

export default ProtectedRoute;
```

### 2. 更新 App.tsx 路由配置

```typescript
// src/App.tsx
import { Navigate, Route, Routes } from "react-router-dom";
import ProtectedRoute from "./components/common/ProtectedRoute";

// 导入页面组件
import HomePage from "./pages/HomePage";
import SearchPage from "./pages/SearchPage";
import CreatePage from "./pages/CreatePage";
import LearningPage from "./pages/LearningPage";
import CourseDetailPage from "./pages/CourseDetailPage";
import EditProfilePage from "./pages/EditProfilePage";
import LoginPage from "./pages/LoginPage";
import ProfilePage from "./pages/ProfilePage";
import RegisterPage from "./pages/RegisterPage";

function App() {
  return (
    <Routes>
      {/* 公开路由 - 无需登录 */}
      <Route path="/" element={<HomePage />} />
      <Route path="/search" element={<SearchPage />} />
      <Route path="/login" element={<LoginPage />} />
      <Route path="/register" element={<RegisterPage />} />

      {/* 受保护的路由 - 需要登录 */}
      <Route
        path="/profile"
        element={
          <ProtectedRoute>
            <ProfilePage />
          </ProtectedRoute>
        }
      />
      <Route
        path="/profile/edit"
        element={
          <ProtectedRoute>
            <EditProfilePage />
          </ProtectedRoute>
        }
      />
      <Route
        path="/create"
        element={
          <ProtectedRoute>
            <CreatePage />
          </ProtectedRoute>
        }
      />

      {/* 其他路由 */}
      <Route path="/post/:id" element={<CourseDetailPage />} />
      <Route path="/learn" element={<LearningPage />} />

      {/* 404 重定向 */}
      <Route path="*" element={<Navigate to="/" replace />} />
    </Routes>
  );
}

export default App;
```

### 3. 登录页面处理重定向

```typescript
// src/pages/LoginPage.tsx
import { useNavigate, useSearchParams } from "react-router-dom";
import { useAuth } from "../context/AuthContext";

const LoginPage = () => {
  const navigate = useNavigate();
  const [searchParams] = useSearchParams();
  const { login } = useAuth();

  // 获取重定向 URL
  const redirectUrl = searchParams.get("redirect") || "/";

  const handleLogin = async (credentials: LoginRequest) => {
    try {
      await login(credentials);
      // 登录成功后重定向回原页面
      navigate(decodeURIComponent(redirectUrl), { replace: true });
    } catch (error) {
      console.error("登录失败", error);
    }
  };

  return (
    <div>
      {/* 登录表单 */}
      <form onSubmit={handleLogin}>
        {/* 表单内容 */}
      </form>
    </div>
  );
};
```

## 工作流程

### 完整的认证流程

```
┌─────────────────────────────────────────────────────────┐
│  用户访问受保护页面（如 /profile）                        │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  前端拦截（ProtectedRoute）                               │
│  1. 检查 tokens.accessToken 是否存在                      │
│  2. 如果不存在 → 重定向到 /login?redirect=%2Fprofile      │
│  3. 如果存在 → 渲染页面组件                               │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  用户登录                                               │
│  1. 输入用户名和密码                                     │
│  2. 调用登录 API                                         │
│  3. 后端验证并返回 JWT token                             │
│  4. 前端保存 token 到 localStorage                        │
│  5. 更新 AuthContext 状态                                │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  重定向回原页面                                           │
│  1. 读取 redirect 参数                                    │
│  2. 导航到原页面（如 /profile）                           │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  页面加载并调用 API                                       │
│  1. ProtectedRoute 检查通过                              │
│  2. 渲染页面组件                                         │
│  3. 调用 API（如 /api/v1/knowposts/mine）                │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  后端拦截（Spring Security）                              │
│  1. 从请求头读取 Authorization: Bearer <token>           │
│  2. 验证 JWT token 签名和有效期                          │
│  3. 如果有效 → 返回数据                                  │
│  4. 如果无效 → 返回 401 Unauthorized                      │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  前端处理响应                                             │
│  1. request.ts 拦截器处理响应                            │
│  2. 如果 401 → 跳转到 /login                             │
│  3. 如果 200 → 显示数据                                  │
└─────────────────────────────────────────────────────────┘
```

## 常见问题

### Q1: 为什么不只在后端保护？

**A:** 后端保护是必须的，但前端拦截可以：
- 提供更好的用户体验
- 避免不必要的 API 调用
- 减少服务器负载
- 防止页面闪烁

### Q2: ProtectedRoute 会影响性能吗？

**A:** 影响很小：
- 只在路由切换时检查一次
- 使用 React Context，性能优化良好
- 比调用 API 后再跳转更快

### Q3: 如何处理 token 刷新？

**A:** 在 AuthContext 中实现：
```typescript
const refresh = async () => {
  try {
    const newTokens = await refreshApiCall();
    setTokens(newTokens);
  } catch (error) {
    // 刷新失败，跳转到登录页
    logout();
  }
};
```

### Q4: 公开路由需要保护吗？

**A:** 不需要：
- 首页、搜索页、登录页、注册页等公开页面
- 不需要 ProtectedRoute 包裹
- 用户可以直接访问

### Q5: 如何测试拦截是否生效？

**A:** 测试步骤：
1. 清除 localStorage（删除 token）
2. 访问受保护页面（如 /profile）
3. 应该立即跳转到 /login
4. 登录后应该重定向回原页面

## 总结

### 核心要点

1. **双重保护是最佳实践**
   - 前端拦截优化用户体验
   - 后端保护确保数据安全

2. **ProtectedRoute 是关键组件**
   - 检查认证状态
   - 重定向未登录用户
   - 渲染已登录用户内容

3. **与现有机制联动**
   - 使用 AuthContext 获取认证状态
   - 使用 request.ts 处理 API 响应
   - 使用 React Router 管理路由

4. **用户体验优先**
   - 立即跳转，无错误信息
   - 保存重定向 URL
   - 登录后返回原页面
