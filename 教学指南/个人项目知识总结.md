## 小阶段总结

### 第一阶段：基础环境搭建

#### 【后端】

**项目初始化**
- Spring Boot 3.2.4 项目创建，Java 21，Maven 构建
- `pom.xml` 管理依赖：Spring Data Redis、MyBatis、Spring Security、OAuth2 Resource Server、Redisson、Caffeine、Canal、Kafka、Elasticsearch、Spring AI、Alibaba OSS
- 使用 `<dependencyManagement>` 统一管理 Spring AI 版本（BOM 方式）
- 数据库：MySQL 8.0，库名 `zhiguang`，`db/schema.sql` 定义表结构（users、know_posts、outbox、following、follower、login_logs 等）
- 关注点：依赖版本冲突预防（Canal 与 Spring Boot 3.2 的 Jackson 兼容性需检查）

**安全配置 — `SecurityConfig.java`**
- 使用 `SecurityFilterChain` Bean（Spring Security 6.x 新 API，不再继承 `WebSecurityConfigurerAdapter`）
- CSRF 禁用（无状态 API）、Session 管理设为 `STATELESS`
- 公开端点：`/api/v1/auth/**`、`/actuator/health`、`/actuator/info`
- 其余请求均需认证，使用 `BearerTokenAuthenticationFilter`
- CORS 当前允许所有来源（TODO：后续改为白名单）
- 实际用途：为后续 JWT 认证打下基础框架

**认证配置 — `AuthConfiguration.java` + `AuthProperties.java` + `PemUtils.java`**
- `AuthProperties` 使用 `@ConfigurationProperties(prefix = "auth")` 绑定配置，包含 RSA 密钥路径、Token 过期时间（access 2h、refresh 7d）、验证码间隔（60s）
- `PemUtils` 从 PEM 文件读取 RSA 公/私钥，用于 JWT 的 RS256 签名/验证
- `JwtEncoder` 使用 `RSAKey` + `RSAPublicKey/RSAPrivateKey` 构造
- `PasswordEncoder` 使用 `BCryptPasswordEncoder`，强度 12
- 关注点：密钥路径配置在 `application.yml` 中，路径为 `classpath:keys/private.pem` 和 `classpath:keys/public.pem`

**Redisson 配置 — `RedissonConfig.java`**
- 使用 `Config.useSingleServer()` 模式连接 Redis
- 地址从配置属性读取，格式为 `redis://host:port`
- 实际用途：为后续分布式锁、限流等场景提供 Redisson 客户端

**线程池配置 — `ThreadPoolConfig.java`**
- 定义多个 `ThreadPoolTaskExecutor` Bean，每个有独立的 name prefix（如 `async-`、`oss-`）
- 使用 `CallerRunsPolicy` 拒绝策略（背压：队列满时由调用线程执行）
- 配置 `waitForTasksToCompleteOnShutdown = true` + `awaitTerminationSeconds`，确保优雅关闭
- 实际用途：异步任务（如 OSS 上传、Canal 消息处理）不阻塞主线程

**缓存配置 — `CacheConfig.java` + `CacheProperties.java`**
- Caffeine 本地缓存：多个命名缓存（如 `feed`、`user`），配置 `expireAfterWrite` 和 `maximumSize`
- `CacheProperties` 定义各缓存的 TTL 和容量上限
- 实际用途：为后续 Feed 流的三级缓存（Caffeine L1 → Redis L2 → Redis 分片 L3）提供基础

**Elasticsearch 配置 — `ElasticsearchConfig.java` + `EsProperties.java`**
- `RestClient` + `RestClientTransport` + `ElasticsearchClient` 三层构建
- `EsProperties` 混合使用 `@ConfigurationProperties` 和 `@Value` 绑定 host 和 index
- 关注点：需添加 null 保护和 `@PreDestroy` 关闭 RestClient

## 全部知识点

### 后端核心知识点

**Spring Security 6.x API**
- 废弃 `WebSecurityConfigurerAdapter`，改用 `@Bean SecurityFilterChain` 方式
- 无状态 API 需禁用 CSRF：`.csrf(csrf -> csrf.disable())`
- Session 管理设为 STATELESS：`.sessionManagement(s -> s.sessionCreationPolicy(STATELESS))`
- JWT 认证通过 `BearerTokenAuthenticationFilter` 实现

**JWT RS256 签名**
- 使用 RSA 公私钥对（PEM 格式），非对称加密
- 私钥签名 Token，公钥验证 Token，适合分布式场景
- Spring Security 提供 `JwtEncoder`/`JwtDecoder` 接口

**BCrypt 密码加密**
- `BCryptPasswordEncoder(strength)` 控制计算轮数，默认 10，项目使用 12
- 不可逆加密，每次生成不同哈希（内含随机 salt）

**Redis 三级缓存架构**
- L1：Caffeine 本地缓存（JVM 内，极速但容量有限）
- L2：Redis 整页缓存（共享，中等延迟）
- L3：Redis 分片缓存（按数据块拆分，支持局部命中）
- 配合热点检测 + 单飞（single-flight）去重

**Redis Bitmap 计数**
- 用位图存储用户点赞/收藏状态，每位代表一个用户
- 分片设计（每个 Bitmap 限制容量）避免超大 key
- Lua 脚本保证原子操作
- 采样一致性检查 + 自愈重建机制

**Outbox 模式**
- 业务操作与消息写入同一事务（`outbox` 表）
- Canal 订阅 MySQL binlog，将 outbox 消息转发到 Kafka
- 保证消息不丢失、不重复（至少一次投递）

**CallerRunsPolicy 背压**
- 线程池队列满时，由调用线程自己执行任务
- 自然形成背压（back-pressure），防止任务无限堆积
- 适用于对吞吐量不敏感但要求可靠执行的场景

**优雅关闭线程池**
- `setWaitForTasksToCompleteOnShutdown(true)`：等待剩余任务完成
- `setAwaitTerminationSeconds(n)`：最长等待 n 秒
- 防止应用关闭时正在执行的任务被中断

### 前端核心知识点

**Vite 路径别名配置**
- `vite.config.ts` 中 `resolve.alias` 使用 `fileURLToPath(new URL("./src", import.meta.url))` 构建绝对路径
- 对应 `tsconfig.json` 中 `paths: { "@/*": ["src/*"] }`
- 两者需同步，否则 IDE 能解析但 Vite 构建失败（或反之）

**tsconfig.json 分离编译**
- 主 `tsconfig.json` `include: ["src"]` 编译业务代码
- `tsconfig.node.json` `include: ["vite.config.ts"]` 编译构建配置
- 主配置通过 `references` 引用 node 配置，避免 vite.config.ts 被业务 TS 编译器处理

**CSS Modules**
- 样式文件命名：`ComponentName.module.css`
- 导入方式：`import styles from './ComponentName.module.css'`
- 使用方式：`className={styles.className}`
- 类名在构建时被哈希化，避免全局冲突
- 全局样式（CSS 变量等）放在 `index.css`，不使用 `.module.css` 后缀

**React Router 6**
- `<BrowserRouter>` 包裹整个应用
- `<Routes>` + `<Route path="..." element={<Component />} />` 定义路由
- `<Outlet />` 在布局组件中渲染子路由
- `<NavLink>` 带 `isActive` 判断当前路由状态
- `useNavigate()` 编程式跳转，`useLocation()` 获取当前路径（用于保存来源路径实现"登录后返回"）

**原生 fetch 封装**
- 不使用 Axios，用原生 `fetch` + `async/await`
- 自动拼接 `VITE_API_BASE_URL` 前缀
- 自动附加 `Authorization: Bearer <token>` 请求头
- 拦截 401/403 状态，清除本地 token 并跳转登录页
- 支持 FormData（检测实例类型，跳过 `Content-Type: application/json`）

**React Context 状态管理**
- `createContext()` + `useContext()` 实现全局状态
- `AuthProvider` 包裹应用，提供 `user`、`tokens`、`isLoading` 状态
- `login()`、`register()`、`logout()`、`refresh()` 操作
- localStorage 持久化 tokens（`zhiguang_auth_tokens`）和用户信息（`zhiguang_current_user`）
- 自动刷新：定时器检查 token 是否接近过期，提前调用 refresh

**主题 Token 管理**
- CSS 变量（`index.css`）：供 CSS 使用，支持 `var()` 引用
- JS Token 对象（`theme/tokens.ts`）：供 TS/JS 代码使用
- 两者应保持同步，理想情况下从单一数据源生成
