# 2026-04-25 工作日志

## 修复 useInfiniteScroll 闭包陷阱 Bug
- **问题**：`zhiguang_new/src/hooks/userInfiniteScroll.ts` 中无限滚动 hook 的 page 参数始终为 1
- **根因**：React 闭包陷阱（Stale Closure）—— `loadMore` 用 `useCallback` 创建时闭包捕获了 `page` 的初始值 1，但 `page` 不在依赖数组中，导致函数永远读到旧值
- **修复**：将 `page` 从 `useState` 改为 `useRef`，同时将 `loading`、`hasMore` 也用 ref 同步，observer 回调里读 ref 而非闭包中的 state 快照
- **关键原则**：在 useCallback/useEffect 闭包中需要读取"最新值"时，用 ref 而非 state；state 适用于需要触发重渲染的场景
- **二次修复**：仅把 page 改成 ref 还不够，因为 HomePage 传入的 `fetchFeed` 是内联函数，每次渲染新引用，导致 `loadMore` 因依赖 `fetchFn` 而无限重建，触发 `useEffect([loadMore])` 反复调用。同时 `loadingRef` 通过 `useEffect` 延迟同步有时序漏洞
- **最终方案**：`fetchFn` 也用 ref 保存（`fetchFnRef`）使 `loadMore` 不依赖它；`loadingRef`/`hasMoreRef` 改为同步写入（`setLoadingSync` 直接写 ref + setState）；用 `initializedRef` 防止 StrictMode 双重挂载
- **第三次修复**：增加 null 安全（`resp?.items ?? []`）；Observer effect 依赖加 `items` 确保列表更新后重新绑定哨兵；HomePage 的 `fetchFeed` 包 `useCallback` 稳定引用
- **后端 Bug**：`KnowPostFeedServiceImpl.toFeedItemResponse` 中 `imgUrls` 为空数组时 `img.get(0)` 越界导致 `IndexOutOfBoundsException`，前端收到 null 响应。修复：解析前判 null，取封面前判 `!img.isEmpty()`
